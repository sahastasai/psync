# Machine-checked: why psync's schedules are safe

`Schedule.lean` models a program as operations on a state, each with a footprint (what it may read
and write), and proves in Lean 4 (core library only, no Mathlib):

| Theorem | Statement |
|---|---|
| `commute` | two independent operations (neither writes what the other reads or writes) commute |
| `interleave_correct` | any interleaving of two pairwise independent chains, each kept in order, equals running one chain and then the other |
| `level_correct` | the same for any number of chains: what a level's join does |
| `levels_correct` | a schedule of levels, each run concurrently in any interleaving, equals running every chain in order |
| `reorders_correct` | an order that moves operations earlier only past independent ones equals the program as written |
| `speculation_harmless` | operations that write nothing leave the state unchanged, so the reads psync may run past an exit change nothing |
| `replay_correct` | running every statement, recording its exit outcome and replaying the first exit in program order gives the state and the exit of sequential execution, when nothing after the first exit writes |
| `recording_slot` | a statement that records its outcome in its own slot is an ordinary operation whose slot holds that outcome, so the theorems above cover it |

Together: the concurrent execution of psync's schedule ends in the state the sequential program
ends in, provided the footprints are right and psync draws an edge between every pair of
operations that are not independent. Those are the obligations of the access and effect analyses,
which `cargo psync check` verifies against the compiled callees.

Not modeled: the generated Rust (rustc type- and borrow-checks it).

## Building everything

```sh
cd verify && lake build                       # Schedule, Tutorial, World, Cert
../scripts/certify.sh                         # from the root: regenerate Certs.lean and check it
```

## Certified schedules: `Cert.lean`, `Certs.lean`

`Cert.lean` defines certificates (each statement's places, and the levels of chains) and a
decidable checker, and proves `check_sound`: if `check c = true`, every run of the schedule equals
the program, for any meaning of the statements under which the certificate's independence holds.
`Certs.lean` is generated by `psync-cert` from the repository's annotated functions; each theorem
there is `check cN = true := by decide`.

## The outside world: `World.lean`

`Schedule.lean` is about the client's state. `World.lean` adds a server, as an abstract labelled
transition system (reads that change server state included), and a commutativity specification
of which requests commute. The book chapter is *What psync guarantees about the outside world*.

| Theorem | Statement |
|---|---|
| `Sys.levels_correct`, `Sys.reorders_correct` | the scheduling theorems, for any state and any independence relation under which steps commute |
| `world_commute` | two statements with disjoint client footprints, distinct calls and spec-commuting requests commute in the world: same client state, server state and responses |
| `world_levels_correct` | if the spec is sound for the server, every execution of psync's schedule ends with the sequential program's client state, server state, and response for every call |
| `empty_spec_sound` | the empty spec (no two requests commute) is sound for every server |
| `kvSpec_sound`, `get_count_not_commute` | a counting server: two `get`s commute; a `get` and a `count` do not |
| `psync_rule_unsound_for_counters` | psync's built-in rule ("two reads commute") is unsound for that server, so the guarantee is relative to the spec |

`Footprint.lean` proves the hypothesis `hind` of `check_sound` for a fragment of MIR: places with
projections, assignments, aggregate moves, `if`, `while`, and calls that pass places by
reference, with per-function summaries.

| Theorem | Statement |
|---|---|
| `frame`, `dep` | under summaries that pass the link check (`Valid`), a statement changes nothing outside its writes, and its writes depend only on what it touches |
| `memSys` | statements with disjoint footprints commute (via `World.upd_comm`) |
| `hind_of_cover` | a certificate whose nodes cover the footprints: certificate independence implies disjoint footprints |
| `mir_schedule_sound` | `check_sound` with `hind` discharged: valid summaries, covering certificate, `check` accepts, so every run of the schedule equals the sequential one |
| `Program.valid`, `prog_valid`, `callers_sound` | the link check decided for a finite program; a recursive callee called on two fields, in one level, proved equal to the calls in order |

```sh
lean verify/Schedule.lean      # Lean 4.22; prints nothing when every proof checks
lean verify/Tutorial.lean      # the book's Lean introduction (Foundations, "Proofs") and its exercise solutions
lean verify/World.lean         # the schedule against a server, relative to a commutativity spec
cd verify && lake build PsyncVerify   # everything, including Cert.lean and Footprint.lean
```

The proofs use only Lean's standard axioms (`propext`, `Classical.choice`, `Quot.sound`) and
contain no `sorry`.
